# หมอท้อง ; AI Thai Postnatal Care

ระบบอัจฉริยะเชื่อมโยงการดูแลมารดาหลังคลอดแบบบูรณาการตามศาสตร์การแพทย์แผนไทย
> AI ไม่ได้วินิจฉัยแม่ แต่ AI รู้ว่าแม่ต้องการการดูแลอะไร และรู้ว่าเมื่อใดต้องส่งต่อให้คน

ต้นแบบนี้ (Phase 1–2: Digitalize + Rule-based AI Screening) แสดงแนวคิด 5 ชั้น **Collect → Screen → AI Analyze → Thai Traditional Medicine Care → Follow-up**

## ⚠️ ข้อสำคัญ
กฎความเสี่ยง ช่วงวันที่พิจารณาหัตถการ และฐานข้อมูลสมุนไพร เป็น **ตัวอย่างเพื่อสาธิต** ยังไม่ผ่านการ validate ทางคลินิก
ห้ามใช้ตัดสินใจรักษาจริง ก่อนใช้งานจริงต้องให้สูติแพทย์ ผดุงครรภ์ และแพทย์แผนไทยทบทวน รวมถึงประเมินด้าน PDPA

## รัน (ไม่ต้อง npm install / build — ใช้ Node >= 18 ล้วน)
```bash

PORT=5360 npm start          # เปลี่ยนพอร์ต (พอร์ต 536 < 1024: Linux/macOS อาจต้อง sudo)
npm test                     # เทสต์ Risk Engine + API (76 ข้อ)
cloudflared tunnel --url http://localhost:536
```
ตัวแปร: `PORT` (536) · `HOST` (127.0.0.1 — ให้ tunnel เชื่อมจากเครื่องเดียวกัน) · `DATA_DIR` (./data) · `APP_SECRET` (ถ้าตั้งจะใช้เป็นกุญแจเข้ารหัสแทนไฟล์ `data/secret.key`)

## ความปลอดภัยที่ทำไว้
- รหัสผ่าน scrypt · session แบบ HttpOnly + SameSite=Strict (+Secure เมื่อผ่าน https) · ป้องกัน CSRF (header + ตรวจ Origin)
- ล็อกอินจำกัดความถี่ (เจ้าหน้าที่ 5 ครั้ง/15 นาที, คนไข้ 5 ครั้ง/HN) · ข้อความ error ไม่บอกว่าผิดช่องไหน
- API token (OpenRouter/HIS/LINE) และรูปใบหน้าถูกเข้ารหัส AES-256-GCM ในดิสก์ ไม่เคยส่งกลับไปที่เบราว์เซอร์ · `data/` อยู่ใน .gitignore
- AI: คำถามที่มี red flag **ไม่ถูกส่งให้ LLM** (ตอบส่งต่อด้วยกฎ) · AI ไม่ได้รับชื่อ/HN · มี system prompt ความปลอดภัยที่ผู้ดูแลลบไม่ได้ · จำกัด 20 คำถาม/ชม.
- วันหลังคลอดคำนวณฝั่งเซิร์ฟเวอร์ (คนไข้แก้เองไม่ได้) และ Risk Engine คำนวณซ้ำฝั่งเซิร์ฟเวอร์

## โหมดผู้ใช้ทดสอบ (admin1 เปิด/ปิดที่ ตั้งค่า AI → ระบบผู้ใช้ทดสอบ)
เมื่อเปิด: คนไข้กรอก **HN และชื่ออะไรก็ได้** (ไม่มีนามสกุลระบบเติมให้) → ระบบ **ถามวันที่คลอด + วิธีคลอด** → สแกนหน้าผ่านทุกคน → เข้าแอปเป็นผู้ป่วยจำลอง โดย **วันที่คลอด = D0 และวันนี้ = Dxx อัตโนมัติ** (ใช้ทดสอบการนับ D, แจ้งเตือน D7/D30 ฯลฯ ได้ทันที — ใช้ร่วมกับ "วันที่สมมติ" เพื่อเลื่อนเวลาได้)
- ผู้ใช้ทดสอบเป็นข้อมูลชั่วคราว (ลบเองใน 24 ชม., ไม่เกิน 200 ราย), ไม่ปนกับรายชื่อคนไข้จริง, เจ้าหน้าที่เห็นเป็นป้าย "ทดสอบ", admin1 ลบทั้งหมดได้
- ⚠️ ขณะเปิดโหมดนี้ **ใครก็เข้าได้** และคนไข้จริงเข้าด้วยวิธีปกติไม่ได้ — เปิดเฉพาะตอนสาธิต/ทดสอบ

## แชท "AI หมอท้อง"
พิมพ์ถามได้อิสระตลอดเวลา (แม้ระหว่างคัดกรอง): ① ข้อความที่มี red flag → ส่งต่อโรงพยาบาลทันที ② ถ้าเปิด AI (OpenRouter) → AI ตอบ ③ ถ้าไม่เปิด/AI ล้มเหลว → ตอบจากฐานความรู้ที่ admin1 บันทึก + FAQ ในระบบ (`server/chatbot.js`, เนื้อหาตัวอย่างต้องให้ผู้เชี่ยวชาญทบทวน) ④ ไม่พบเรื่องที่ถาม → แสดงคำแนะนำให้ลองพิมพ์ หรือกด "เริ่มคัดกรองอาการ"

## ตรวจยา/สมุนไพร
ค้นหาโดยพิมพ์ หรือกด ▾ เลือกจากรายการแบ่งกลุ่ม ยา · สมุนไพร · อาหารเสริม · อาหาร (admin1 เพิ่มรายการและกำหนดข้อห้ามได้ที่แท็บ "เนื้อหา"; รายการตัวอย่างของระบบติดป้าย "ตัวอย่าง") ถ้าไม่พบชื่อ ระบบตอบ "ควรปรึกษาบุคลากร" เสมอ

## กติกาเพิ่มเติม
- **HN/เบอร์โทรเป็นตัวเลขเท่านั้น** (อนุญาต `-`) ทั้งตอน login และตอน admin1 สร้างคนไข้
- **ความเครียด 4 ระดับ** (แทน EPDS): ไม่เครียด 🟢 · เล็กน้อย 🟡 · มีมาก 🟠 · อยากฆ่าตัวตาย 🔴 (แสดงสายด่วน 1323)
- **ปุ่มแผนที่:** แดง → โรงพยาบาลใกล้ฉัน · ส้มกลุ่มแพทย์แผนไทย (คัดตึงเต้านม/น้ำนมน้อย) → คลินิกแพทย์แผนไทยใกล้ฉัน · ส้มทางการแพทย์ (ไข้ ความดัน ความเครียดมาก ฯลฯ) → ไม่มีปุ่ม ให้บุคลากรประเมิน
- **ยังอยู่โรงพยาบาลหลังคลอด** (คลอดปกติ 48 ชม. = D0–D2, ผ่าคลอด 72 ชม. = D0–D3, แก้ได้ที่ admin1 → ตั้งค่า AI): ถ้าผลเป็นส้มหรือแดง จะแจ้ง **"กรุณาแจ้งพยาบาลในแผนก"** แทนปุ่มแผนที่
- **โหมดผู้ใช้ทดสอบ:** วันที่คลอดเลือกได้เฉพาะวันนี้หรือก่อนหน้า · อายุ/อายุครรภ์/สิทธิ์ถูกจำลองให้อัตโนมัติ · เมื่อเปิดโหมดนี้ หน้า login แสดงเลขเวอร์ชันต่อท้ายว่า `test beta` (หายไปเมื่อปิดโหมด)

## สถานพยาบาลใกล้ตัว
เจ้าหน้าที่เพิ่ม/แก้/ลบโรงพยาบาลและคลินิกแพทย์แผนไทยที่แท็บ "สถานพยาบาล (แผนที่)" (ปักหมุดบนแผนที่ OpenStreetMap, ลากปรับ, หรือกด GPS ของเครื่อง) · คนไข้กดปุ่มแล้วเห็น **แผนที่ในแอป** (Leaflet + OpenStreetMap ไม่ต้องออกไปที่ Google) แสดงตำแหน่งของตัวเอง + สถานที่ที่เจ้าหน้าที่เพิ่ม (⭐ มาก่อน) **รวมกับ** สถานที่ใกล้เคียงจากข้อมูล OpenStreetMap (ตัดรายการซ้ำ: ชื่อเดียวกันหรืออยู่ห่าง <150 ม. ให้ใช้ของเจ้าหน้าที่) เรียงตามระยะทาง พร้อมปุ่มโทร / ดูบนแผนที่ / นำทาง (เปิด OpenStreetMap directions) · ข้อมูลใกล้เคียงดึงผ่านเซิร์ฟเวอร์ (Overpass API, แคช 24 ชม., ปัดพิกัดเป็น ~1 กม., ตั้ง `OVERPASS_URL` ได้) ถ้าออนไลน์ไม่ได้ยังแสดงสถานที่ที่เจ้าหน้าที่เพิ่ม · ข้อมูล OSM บางพื้นที่ยังไม่ครบ โดยเฉพาะคลินิกแพทย์แผนไทย จึงควรให้เจ้าหน้าที่เพิ่มสถานที่หลักเอง · ไลบรารีแผนที่ (Leaflet) เก็บในโปรเจกต์ แต่ภาพแผนที่โหลดจาก tile.openstreetmap.org (ต้องมีอินเทอร์เน็ต; ใช้งานปริมาณมากควรใช้ผู้ให้บริการ tile ของตัวเอง) · GPS ต้องเปิดผ่าน https หรือ localhost

## กติกาของระบบ (ตามที่ผู้จัดทำกำหนด)
- **D0 = วันคลอด**, D1 = วันถัดไป · ประเมินได้ทุกวันตั้งแต่ D1 · กรอกย้อนหลังได้ (เช่น ลืมกรอก) หรือเว้นวันได้ แต่กรอกล่วงหน้าไม่ได้ · ผลของแต่ละวันมีได้ 1 ผล (บันทึกซ้ำ = แทนที่)
- **แจ้งเตือนฟื้นฟูมารดาหลังคลอด 5 ครั้ง ทุกวัน:** คลอดทางช่องคลอดเริ่ม **D7** (D7–D11) · ผ่าคลอดเริ่ม **D30** (D30–D34) — ขึ้นเป็น **กล่องข้อความทันทีที่เข้าแอป** และมี **กระดิ่ง** ข้างไอคอนผู้ใช้
- **สีแดง** → แจ้งให้ไปพบแพทย์ + ปุ่ม GPS โรงพยาบาลใกล้ตัว · **สีส้ม** กลุ่มแพทย์แผนไทย (คัดตึง/ปวดตึงเต้านม, น้ำนมไหลน้อย) → ปุ่ม GPS คลินิกแพทย์แผนไทยใกล้ตัว · สีส้มจากสาเหตุทางการแพทย์ (ไข้ ความดันสูง ฯลฯ) → ให้บุคลากรประเมินโดยเร็ว + ตัวเลือกทั้งสองปุ่ม
- **HN ใส่ `-` หรือไม่ใส่ก็ได้** (`69-0005` = `690005`) · ค่าเริ่มต้นของฐานข้อมูลใหม่คือคนไข้ mockup 10 ราย (ปิดด้วย `SEED_MOCK=0`, โหลดเพิ่มได้ที่หน้า admin1)
- **โหมดสาธิต (mockup) สแกนหน้า:** เปิดไว้เป็นค่าเริ่มต้น — ผ่านขั้นที่ 1 แล้วระบบเปิดกล้องแสดงการสแกนและ "ผ่านทุกคน" (ไม่เทียบใบหน้า ไม่โหลดโมเดล ไม่ส่งรูป) ปิดได้ที่ admin1 → ตั้งค่า AI (หรือเริ่มด้วย `FACE_MOCK=0` สำหรับฐานข้อมูลใหม่)
- **วันที่สมมติ:** admin1 ตั้งวันที่ของระบบได้ (ตั้งค่า AI → วันที่ของระบบ) เพื่อสาธิตการนับ D และแจ้งเตือนโดยไม่ต้องรอ

## ยกเลิก/เปิดการสแกนหน้า
admin1 → ตั้งค่า AI → "สแกนหน้าตอนเข้าระบบ": **ปิด (ค่าเริ่มต้น)** = กรอก HN/เบอร์โทร + ชื่อแล้วเข้าได้เลย ไม่เปิดกล้อง (โหมดผู้ใช้ทดสอบก็ข้ามสแกนเช่นกัน) · **เปิด** = ใช้ขั้นสแกนหน้า (โหมดสาธิตผ่านทุกคน หรือเทียบใบหน้าจริงที่ลงทะเบียนไว้) — ตัวแปร `FACE_SCAN=1` ใช้กำหนดค่าเริ่มต้นของฐานข้อมูลใหม่ · ⚠️ เมื่อปิดสแกนหน้า ความปลอดภัยของการเข้าระบบเหลือแค่ HN/เบอร์โทร + ชื่อ ซึ่งเดาง่าย แนะนำเปิดสแกนหน้าหรือเพิ่ม PIN ก่อนใช้กับคนไข้จริง

## อัปเดตโค้ดแล้วหน้าเว็บยังเป็นของเก่า?
หลัง `git pull` **ต้องรีสตาร์ตเซิร์ฟเวอร์** (Ctrl+C แล้ว `npm start`) เพราะไฟล์หน้าเว็บอ่านสดจากดิสก์ แต่โค้ดฝั่งเซิร์ฟเวอร์โหลดตอนเริ่มทำงานเท่านั้น ถ้าไม่รีสตาร์ตจะได้ผสมเวอร์ชัน · ระบบช่วยป้องกัน: ไฟล์แอปไม่ถูก cache (`no-store`, ใช้กับ Cloudflare ด้วย) · URL ของ .js/.css มีรหัสเวอร์ชัน `?v=…` · หน้าเว็บเทียบเวอร์ชันกับเซิร์ฟเวอร์และรีโหลดตัวเองหนึ่งครั้งถ้าเก่า · หน้า admin/staff ขึ้นแถบแดงเตือนถ้าโค้ดบนดิสก์ใหม่กว่าโปรเซสที่รันอยู่ · หน้า login มีรหัสเวอร์ชันเล็ก ๆ (เช่น `v0bbcc8ae`) ไว้เทียบ

## ข้อจำกัดที่ต้องรู้ก่อนใช้กับข้อมูลจริง
- **โหมดสาธิตเปิดอยู่ = ใครรู้ HN/เบอร์โทร + ชื่อก็เข้าได้** ใช้กับข้อมูลสมมติเท่านั้น ก่อนใช้กับคนไข้จริงต้องปิดโหมดนี้และลงทะเบียนใบหน้า
- **สแกนใบหน้าเป็นปัจจัยเสริม ไม่ใช่การพิสูจน์ตัวตนที่แข็งแรง**: ตรวจกะพริบตา (liveness) ทำงานบนเบราว์เซอร์ จึงกันการยกรูปถ่ายมาสแกนหน้ากล้องได้ แต่ผู้ที่ปลอมคำขอเอง (มีรูปเป้าหมาย + HN/เบอร์ + ชื่อ) ยังอาจหลอกได้ เพราะเซิร์ฟเวอร์ไม่เห็นวิดีโอ · HN/เบอร์โทร + ชื่อบางส่วนเดาได้ง่าย แนะนำเพิ่มปัจจัยที่สาม เช่น PIN ที่ รพ. ให้ตอนจำหน่าย
- กล้องต้องเปิดผ่าน **https หรือ localhost** (Cloudflare Tunnel เป็น https อยู่แล้ว)
- ใบหน้าเป็นข้อมูลชีวมิติ/ข้อมูลสุขภาพตาม PDPA — ต้องมีฐานกฎหมาย/ความยินยอม, นโยบายการเก็บ-ลบ, และผ่านการประเมินความเสี่ยงก่อนใช้จริง
- ฐานข้อมูลเป็นไฟล์ JSON (เหมาะกับต้นแบบ/คลินิกเล็ก) — session อยู่ในหน่วยความจำ (รีสตาร์ตแล้วต้องล็อกอินใหม่) ก่อนขยายผลควรเปลี่ยนเป็น DB จริง + backup
- ผ่าน Cloudflare Tunnel จะเปิดสู่สาธารณะ: ควรเปลี่ยนรหัสผ่านทันทีก่อนเปิด tunnel และพิจารณาใส่ Cloudflare Access หน้า `/admin/` และ `/staff/`
- การเรียก HIS API ทำจากเซิร์ฟเวอร์ตาม URL ที่ admin1 ตั้ง (admin1 เป็นผู้ที่ไว้ใจได้เท่านั้น)

## โครงสร้าง
- `server/` API + static server (`index.js`, `store.js`, `security.js`) · `web/admin/` และ `web/staff/` หน้าจัดการ · `web/vendor/face-api/` ไลบรารีสแกนใบหน้า (MIT) + โมเดล เก็บในโปรเจกต์ ไม่พึ่ง CDN
- `web/risk-engine.js` กฎจัดระดับความเสี่ยง · `web/ttm.js` ข้อห้าม/ช่วงเวลาหัตถการ (ค่า placeholder ใน `WINDOWS`)
- `web/herbs.js` ฐานข้อมูลสมุนไพรตัวอย่าง · `web/app.js` UI

## สิ่งที่ยังไม่ได้ทำ (Roadmap)
DB จริง/ปัจจัยยืนยันตัวตนที่สาม/liveness · LINE Webhook รับ userId อัตโนมัติและส่งแจ้งเตือนตามกำหนดอัตโนมัติ · แผนที่และสถานพยาบาลใกล้ฉัน · OCR ฉลากยา · แบบประเมินธาตุเจ้าเรือน · เชื่อม HIS/EMR · ML/Predictive (Phase 5) · Regional platform (Phase 6) · การทดสอบ validation กับข้อมูลจริง
